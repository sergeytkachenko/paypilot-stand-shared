# PayPilot — архітектурний опис

## Компоненти й потоки даних

```
                        ┌─────────────────────────────┐
   GET  /       ──────► │  app/main.py (FastAPI)       │  chat UI (static)
   POST /chat   ──────► │   chat surface + test API    │
   /api/_test/* ──────► │   + /compare (clean vs prof) │
                        └───────────────┬──────────────┘
                                        │
                            ┌───────────▼───────────┐
                            │ app/agent/loop.py      │  власний цикл оркестрації
                            │  model → tool → model  │
                            └───┬──────────┬─────────┘
             prompt.build()     │          │   dispatch(name, args)
            (base.v1 + overlays)│          │
                  ┌─────────────▼──┐   ┌───▼───────────────┐
                  │ providers/*    │   │ app/agent/tools.py│
                  │ mock/anthropic │   │  9 інструментів    │
                  │ /openai        │   └───┬───────────────┘
                  └────────────────┘       │ виклики
                          ┌────────────────┼───────────────┬──────────────┐
                          ▼                ▼                ▼              ▼
                   app/engines/*    app/db.py        app/rag/         app/clock.py
                   fx/limits/       SQLite state     retriever        CLOCK_OVERRIDE
                   disputes         (reset→seed)     kb_clean/broken
                   (оракул)
                          │
                    app/tracing.py  ── дерево спанів → traces/traces.jsonl + API
```

## Ключові рішення

- **Власний цикл оркестрації**, не фреймворк. Цикл `model → tool → model`
  явний у [loop.py](../app/agent/loop.py). Це навмисно: частина поведінки,
  яку ви досліджуватимете, живе саме в оркестрації, а не в моделі й не в
  інструментах, і в чужому фреймворку її не було б видно.
- **Рушії як оракул** ([engines](../app/engines)) — детермінований код, що
  рахує правильну відповідь. Звичайний Python, без агента й без моделі:
  імпортується в тест і дає еталон програмно. Це те, з чим порівнюють, коли
  треба довести, а не переконати.
- **Гачки в агентному шарі, не в рушіях.** Інструмент може викривити результат
  рушія, але сам рушій лишається правильним — інакше зник би оракул. Тобто
  розбіжність між `tool.result` і прямим викликом рушія завжди означає щось
  конкретне.
- **Провайдер-адаптер** ([providers](../app/agent/providers)) — нейтральний
  внутрішній формат повідомлень; mock (без ключа, детермінований), Anthropic,
  OpenAI. Перемикається змінною `LLM_PROVIDER`.
- **Профілі й overlay** — частина поведінки вмикається накладанням фрагментів
  на `prompts/base.v1.md` без правки базового файлу. Зібраний промпт завжди
  видно через `GET /api/_test/prompt`.
- **Трасування** — власний in-process трейсер (стабільний JSONL + API) плюс
  дзеркалювання в Phoenix через OTLP. API і файл працюють завжди, навіть коли
  колектор не піднятий: ваші перевірки не залежать від зовнішнього сервісу.
- **Чат-UI** — один статичний файл без збірки (`app/static/index.html`):
  перемикач профілів, порівняння з `clean` і ×5, довідник еталонних значень,
  розширені налаштування (точкове вмикання, час, пам'ять і пошук, дерево
  спанів останнього ходу, скидання стану); UA/EN, світла й темна тема.

## Життєвий цикл запиту `/chat`

1. `loop.run_turn` бере або створює сесію, будує system prompt
   (`base.v1` + активні overlay), відкриває кореневий спан `agent.request`.
2. Якщо перевищено поріг згортки (`SUMMARIZE_AFTER_STEPS`) — рання частина
   історії замінюється зведенням, спан `agent.summarize`.
3. Цикл: `llm.call` → якщо модель повернула tool_calls, кожен виконується
   (спан `tool.<name>` з аргументами й результатом в атрибутах) → результат
   кладеться в контекст → повтор.
4. Фінальна відповідь без tool_calls завершує хід; дерево спанів пишеться
   в пам'ять і в `traces/traces.jsonl`.

Кожен із цих чотирьох кроків спостережуваний. Якщо ви не можете пояснити
поведінку з тексту відповіді — вона майже завжди пояснюється з дерева спанів.

## Порти й запуск

- Чат-UI + API: `http://localhost:8000` — `docker compose up --build -d` або
  `python -m uvicorn app.main:app --port 8000`.
- Phoenix (UI трасування): `http://localhost:6006` — **лише під docker
  compose**. При запуску через uvicorn порт мертвий, і це нормально.
- Трейси: `GET /api/_test/traces/{request_id}` та файл `traces/traces.jsonl` —
  працюють завжди, незалежно від Phoenix.
- Стан: `GET /api/_test/state/{table}`.
