# Встановлення: від порожньої машини до робочого стенду

Покроково, з нуля. Розраховано на людину, яка раніше не піднімала в себе
нічого подібного. Приблизний час — **30–40 хвилин**, більшість із них займає
завантаження.

Стенд запускається через **Docker**. Python, бази даних і решту залежностей
встановлювати не треба — Docker збирає все сам, усередині себе.

Наприкінці у вас у браузері відкриється чат зі стендом і відповість на
запитання.

Кроки йдуть у тому порядку, у якому їх треба робити. Найчастіша поламка на
цьому шляху — запустити стенд раніше, ніж вписаний ключ, тож не міняйте
місцями кроки 3 і 4.

---

## 0. Що знадобиться

| Що | Навіщо |
|---|---|
| **Ключ провайдера** | без нього стенд відповідає заглушками, і завдання на ньому не робляться |
| **Docker Desktop** | запускає стенд |
| Браузер | інтерфейс стенду |

Вільне місце на диску: плануйте **близько 6 ГБ**.

**Реєструватися в Docker не потрібно.** Docker Desktop при першому запуску
пропонує створити акаунт і увійти — це вікно можна закрити. Стенд працює без
входу; акаунт потрібен лише тим, хто публікує власні образи.

---

## 1. Завести ключ

**Ключ ви заводите собі самі** — це частина курсу, як власний ноутбук. Він
ваш, лишається у вас після курсу, і платите за нього ви.

**Закладіть на курс $20.** Один діалог зі стендом коштує приблизно $0.005,
тож самі заняття — це копійки; основна витрата припадає на прогони наборів
перевірок у домашніх завданнях, а вона залежить від того, скільки ви
експериментуєте. $20 покривають це із запасом, і запас тут дешевший за
прогін, який зупинився посеред здачі.

> **Підписка Claude Pro або Max тут не допоможе.** Це окрема система оплати:
> підписка дає claude.ai, а стенд працює через API, і кредити для нього
> купуються окремо. Це найчастіше непорозуміння на цьому кроці — перевірте
> це раніше, ніж шукати помилку в стенді.

### Порядок

1. **Зареєструйтесь у консолі:** [platform.claude.com](https://platform.claude.com).
2. **Settings → Billing → Buy credits.** Оплата передплачена: кладете суму
   наперед, вона списується за фактом використання. Покладіть **$20** — на
   курс цього достатньо. Більше класти не варто: кредити згорають через рік
   і не повертаються. Якщо не впевнені, що картка пройде, зробіть спершу
   мінімальну покупку — це заодно перевірка.
3. **Settings → API keys → Create key.** Назвіть як завгодно, наприклад
   `paypilot`. Ключ — довгий рядок, що починається з `sk-ant-`, і він
   показується **один раз**. Збережіть одразу; не показався — створіть новий,
   старий видаліть.
4. **Поставте собі межу витрат** — це найдешевша страховка від циклу, який ви
   залишили працювати на ніч. **Settings → Workspaces → Create workspace**,
   вкладка **Spend limits**, місячна межа **$20** — стільки ж, скільки ви
   поклали, щоб ліміт ловив аварію, а не звичайну роботу. Ключ створюйте
   всередині цього workspace. На Default Workspace ліміт виставити не можна —
   тому саме окремий.

Якщо ключа ще немає, решту інструкції можна пройти наперед: стенд підніметься
й без нього. Тільки пам'ятайте, що без ключа він відповідає заготовками —
однаково щоразу. Це годиться, щоб переконатися, що середовище зібране, і не
годиться для навчальних завдань.

## 2. Забрати репозиторій

Адресу репозиторію вам дає курс. Два способи, обидва прийнятні.

**Через git** — зручніше, якщо далі будуть оновлення. Потрібен встановлений
git ([git-scm.com/downloads](https://git-scm.com/downloads), під час
встановлення всі параметри можна лишити за замовчуванням):

```bash
git clone <адреса-репозиторію>
```

**Архівом, без git:** на сторінці репозиторію зелена кнопка **Code** →
**Download ZIP**, далі розпакувати.

У будь-якому разі розміщуйте теку так, щоб у шляху не було пробілів і
кирилиці: `C:\paypilot-stand` підійде, `C:\Users\Іван\Мої документи\стенд` —
ні.

Відкрийте цю теку й перевірте, що всередині лежать файли `Dockerfile` і
`docker-compose.yml`. Якщо після розпакування архіву ви бачите всередині ще
одну теку з такою самою назвою, а файли аж у ній — працюйте з внутрішньою.
**Саме ця тека, де лежать ці два файли, далі називається «корінь
репозиторію».** Тримайте її вікно відкритим: вона знадобиться в кроках 3 і 4.

## 3. Вписати ключ — до першого запуску

У корені лежить файл **`.env.example`**. З нього треба зробити копію з назвою
**`.env`** — мишею, набирати нічого не потрібно:

1. Клацніть на `.env.example`, натисніть **Ctrl+C**, потім **Ctrl+V** — поряд
   з'явиться копія.
2. Перейменуйте копію на рівно **`.env`** (клавіша **F2**).

Відкрийте `.env` у Блокноті — правий клік → **Відкрити за допомогою** →
**Блокнот** — і приведіть два рядки до такого вигляду:

```
LLM_PROVIDER=anthropic
ANTHROPIC_API_KEY=sk-ant-...ваш ключ...
```

Три речі, на яких спотикаються найчастіше:

- Файл має називатися рівно **`.env`**, а не `.env.txt`. Windows ховає
  розширення — увімкніть у провіднику «Розширення імен файлів» і перевірте.
- **Без пробілів** навколо `=` і без лапок навколо ключа.
- Якщо стенд уже запущений, після зміни `.env` його треба **перезапустити**:
  `docker compose up -d`. Значення читаються під час старту.

Саме тому цей крок стоїть перед запуском. Стенд, піднятий без `.env`,
стартує успішно й мовчки працює на заглушках — жодної помилки ви не
побачите, а відповіді будуть несправжні.

**Ключ нікуди не комітиться.** `.env` уже прописаний у `.gitignore` — так і
лишіть. Не надсилайте ключ у чат групи й не вставляйте в домашні завдання.

## 4. Підняти стенд

1. Завантажте **Docker Desktop**:
   [docker.com/products/docker-desktop](https://www.docker.com/products/docker-desktop/).
2. Встановіть. На Windows інсталятор сам увімкне **WSL2** і, найімовірніше,
   попросить **перезавантажити комп'ютер** — перезавантажте.
3. Запустіть Docker Desktop і дочекайтесь, доки значок кита перестане
   блимати. Пропозицію увійти в акаунт закрийте.

Далі буде команда, і її треба кудись набрати. **Відкрийте вікно команд у теці
зі стендом** — тій самій, де лежать `Dockerfile` і `docker-compose.yml`:

- **Windows 11:** правий клік на порожньому місці всередині теки →
  **Відкрити в терміналі**.
- **Якщо такого пункту немає:** клацніть у провіднику на **адресний рядок**
  угорі (там, де написаний шлях), наберіть замість нього `powershell` і
  натисніть **Enter**.
- **macOS:** правий клік на теці → **Служби** → **Нова термінальна вкладка**.

Відкриється чорне або синє вікно з курсором, і в першому рядку буде видно
шлях до вашої теки. Оце і означає «виконати команду в корені репозиторію» —
вставити її в **це** вікно (**Ctrl+V**) і натиснути **Enter**.

Перша команда:

```bash
docker compose up --build -d
```

Перший запуск триває **5–10 хвилин**: збирається образ, і рядки бігтимуть
довго. Наступні запуски — секунди. Ознака успіху: останні рядки закінчуються
словом `Started`, і ви знову бачите курсор. **Це вікно не закривайте** —
команда з кроку 5 набирається в ньому ж.

Піднімається дві речі:

- **http://localhost:8000** — чат зі стендом, він же основне робоче місце;
- **http://localhost:6006** — Phoenix, окремий інтерфейс для перегляду трейсів.

Phoenix стартує повільніше за стенд — йому потрібно **близько хвилини**.
Якщо сторінка на 6006 спершу не відкривається, це нормально, дайте їй час.

Корисні команди на потім:

| Команда | Що робить |
|---|---|
| `docker compose down` | зупинити стенд; дані лишаються |
| `docker compose up -d` | підняти знову (без перезбірки) |
| `docker compose logs stand` | подивитися, що стенд пише про себе |
| `docker compose up --build -d` | перезібрати після оновлення репозиторію |

## 5. Перевірити, що все зібралося

Перша перевірка — діагностика. Наберіть у тому самому вікні команд, що й
у кроці 4 (команда виконується **всередині** контейнера):

```bash
docker compose exec stand python scripts/doctor.py
```

Очікуваний результат — усі рядки `[OK]` і підсумок **`Environment is ready.`**

Два відхилення, які трактуються по-різному:

- `phoenix (trace UI) [WARN]` — найімовірніше Phoenix ще піднімається.
  Почекайте хвилину й повторіть команду. Якщо `WARN` лишився, стендом усе
  одно можна працювати: трейси доступні через `GET /api/_test/traces/...` і
  з файлу `traces/traces.jsonl`.
- `llm provider [OK] mock` замість `anthropic` — ключ не підхопився,
  повертайтесь до кроку 3.

Друга перевірка, вона ж найпереконливіша: відкрийте
**http://localhost:8000**, виберіть клієнта **CUS-0001** (перемикач «як …» біля
поля вводу) і напишіть у чат

```
What is my balance?
```

Відповідь має прийти за кілька секунд і виглядати приблизно так:
«Your account balance is EUR 2,450.30 in your EUR account (ACC-1001)…».
Прийшла — стенд живий.

Якщо ви ще без ключа, відповідь виглядатиме дивно: замість речення ви
побачите сирий результат виклику інструмента, щось на кшталт
`Result of get_account: {...}`. Це не поламка, це заглушка. З ключем
відповідь буде нормальним текстом.

## Якщо щось не працює

**Docker Desktop не стартує на Windows.** Майже завжди — вимкнена
віртуалізація в BIOS або не встановлений WSL2. Docker Desktop зазвичай сам
показує посилання на потрібну інструкцію; якщо ні — виконайте `wsl --install`
у PowerShell від адміністратора й перезавантажтесь.

**`docker: command not found` або «cannot connect to the Docker daemon».**
Docker Desktop не запущений. Запустіть його й дочекайтесь, доки значок кита
перестане блимати.

**Діагностика каже `provider: mock`, хоча ключ вписаний.** Три причини за
частотою: файл названо `.env.txt`; пробіли навколо `=`; стенд не
перезапущений після редагування (`docker compose up -d`).

**`HTTP 400` на кожен запит.** Найчастіше — закінчилися кредити або
спрацювала ваша межа витрат. Перевірте баланс у консолі: **Settings →
Billing**. `doctor` покаже повідомлення провайдера зрозумілою мовою.

**Порт 8000 або 6006 зайнятий.** Щось уже слухає цей порт — найчастіше
попередній запуск стенду. `docker compose down` і спробуйте знову.

**Сторінка на localhost:8000 не відкривається.** Перевірте, що контейнери
працюють: `docker compose ps` — обидва мають бути `Up`. Якщо ні,
`docker compose logs stand` покаже причину.

**Дані виглядають зіпсованими, стенд поводиться дивно.** У «Меню › Розширені
налаштування» (розділ «Стенд») є кнопка **«Скинути стан»** — вона повертає
базу до вихідного вигляду.

**Хочу переконатися, що стенд цілий.**
`docker compose exec stand python scripts/ci_smoke.py` — перевіряє всі
поверхні, ключ для цього не потрібен.

Якщо нічого з переліченого не допомогло — надішліть куратору **повний вивід
`doctor`**. У ньому видно майже все, що може бути не так.
